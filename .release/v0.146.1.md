# Codex VL 0.146.1 candidate

This candidate tracks the upstream OpenAI Codex `rust-v0.146.1` patch release
while retaining the Codex VL workflow layer.

## Upstream scope

`rust-v0.146.1` is two commits over `rust-v0.146.0`: a backport of the safer
cyber-model auto-review defaults (`#37057`) plus the release commit. The merge
touched no fork-owned path; the only conflict was the workspace version.

## Preserved fork contracts

- Goal and loop state remain persisted separately, with legacy Vivling loop
  migration reconciliation before normal state migration.
- `/vivling`, `/vl`, `/loop`, and the TUI's local-workflow boundaries remain
  available, and MCP startup keeps its bounded tools-list retry.
- The Vivling background runners keep injecting the live session model and
  build their clients through the core-owned boundary.
- Provider-specific `namespace_tools` configuration remains authoritative.

## Fork-side fixes included

- **The Windows installer no longer hands users upstream Codex.**
  `scripts/install/install.ps1` preferred upstream's distribution channel by
  default and fell back to upstream's GitHub releases, so the fork's name was
  on the installer and someone else's binary at the end of it. It arrived with
  the 0.146.0 merge; `install.sh` never had it. Release resolution is now
  fork-only and asset URLs come from the release's own metadata.
- **The message-history batch reader tolerates unsupported file locks.** The
  ENOTSUP fallback carried on every other advisory lock had never been
  committed here, so `lookup_batch` failed outright on Android/Termux storage
  while the single-entry reader degraded gracefully. Ported verbatim from the
  Termux fork; the two files are now identical.
