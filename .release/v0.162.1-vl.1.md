# Codex VL 0.162.1-vl.1

Fork release on the upstream OpenAI Codex `rust-v0.162.1` base. It also carries
the work of the 0.162.0 line, which only ever existed as the GitHub pre-release
`v0.162.0-vl.1` and never reached npm, and the work staged for the skipped 0.161
line.

## Contents

- Upstream `rust-v0.162.1` merged with the fork feature set intact: Vivling,
  `/loop` and `manage_loops`, the VL UI, fork identity, the Termux and Android
  compatibility guards and the `-vl` managed daemon. The upstream patch release
  fixes a TUI crash on multi-line asynchronous questions (links and line breaks
  are preserved) and limits the daemon feature compatibility checks to explicit
  command-line feature overrides, which removes startup failures caused by a
  running shared server whose settings differ from the client defaults.
- Vivling: a compact one-line layout next to the three-line CRT one. Switch with
  `/vivling layout <full|line>`; the choice is kept under `[vivling] layout` in
  the Codex home `config.toml`, written with a structured TOML edit that keeps
  comments and every other key and never rewrites a config it cannot parse. The
  line layout keeps the animations.
- Loop: a blocked loop job tick (busy turn, review mode, side conversation,
  stuck claim, invalid runner model) is re-armed on a backoff ladder from one
  second doubling up to one minute, instead of re-firing on every refresh and
  spinning at full speed until the turn ends. The persisted occurrence state is
  untouched, and a warning is shown once when a job first settles at the cap.
- TUI: a turn-start latch that the core never acknowledged is cleared after a
  timeout (60 seconds, with a warning first), so queued messages are no longer
  held hostage by a core that stays silent.
- Voice: the packaged voice runtime ships inside the macOS arm64 and the
  glibc Linux packages. The Linux helper links alsa-lib statically, so the
  packages do not depend on a system `libasound`.
- Daemon: `daemon stop` also stops the updater, the update loop ends when the
  fork refuses a standalone update instead of retrying forever, a too-long
  socket path is reported with its limit, and the updater pid record is removed
  when the updater exits.
- Android packages are accepted without a bundled ripgrep; install it with
  `pkg install ripgrep`.
- File locks keep degrading on filesystems that do not implement them
  (Termux storage), including the new control-socket lock paths of the 0.162
  upstream line.
- Provider `namespace_tools` stays configurable per provider.

## Install

```bash
npm install -g @mmmbuto/codex-vl@latest --allow-scripts=@mmmbuto/codex-vl
```

`@latest` points to this release once it is promoted; to pin it, use
`@mmmbuto/codex-vl@0.162.1-vl.1`. The platform builds are published as
`@mmmbuto/codex-vl@0.162.1-vl.1-<platform>` (`linux-x64`, `linux-arm64`,
`android-arm64`, `darwin-arm64`); the main package selects the right one.
The macOS arm64 package is built from source during installation.

## Verification

- The release branch sits on the merge of `rust-v0.162.1` (fork feature
  register applied) plus the release commit.
- Packaging builds run on the public GitHub workflows; the local smoke on the
  built archives is documented in the release report, out of this tree.
