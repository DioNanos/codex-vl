# Codex VL 0.147.0

Tracks the upstream OpenAI Codex `rust-v0.147.0` stable release while retaining
the Codex VL workflow layer.

## Upstream scope

Upstream tagged `rust-v0.147.0` one day after `0.147.0-alpha.13`. The two are
siblings off the same parent and differ only in the workspace version line, so
this release tracks the stable directly. Seventeen conflicting files, the
substantive ones in the state runtime, the TUI app-server event path, the MCP
client and the model protocol.

## Preserved fork contracts

- Goal and loop state remain persisted separately: upstream refactored the state
  DB open path, and the fork's wrapper still runs the VL migration
  reconciliation (device-key renumber, legacy loop migration numbers) around it.
- `manage_loops` still resolves as a dynamic tool call in the TUI. Upstream added
  a rejection path for requests belonging to abandoned side threads; it runs
  first, because it only borrows the request while matching the variant moves it,
  and refusing a request for a closed thread before dispatching it is the right
  order regardless.
- MCP startup keeps its bounded tools-list retry, adapted to upstream's new
  catalog item limit.
- Provider-specific `namespace_tools` configuration remains authoritative,
  alongside upstream's new remote-compaction capability.
- The Vivling crates, `vendor/msa-core` and the `chrono` feature of `schemars`
  remain registered in the workspace.

## Fixed

- **AGENTS.md created mid-session is now discovered.** Discovery cached its
  result under the environment selection, which does not change when a file
  appears, so a session that started without `AGENTS.md` kept reporting that
  none existed even after `/init` wrote one.
- **The model catalog parses again, and a fork guarantee is back.** Upstream
  0.147.0 introduced its own legacy `base_instructions` layer, whose serializer
  flattens `ModelInfo` and adds a `base_instructions` key of its own; with the
  fork field also serialized the catalog carried the key twice and failed to
  parse. Separately the merge had taken upstream's `get_model_instructions()`,
  whose fallback branch returns an empty string where this fork returns
  `base_instructions` — every catalog entry without a template would have
  shipped with no instructions at all. The field is now outside serde and the
  fallback is restored, with a behavioural test that fails if the branch is ever
  emptied again.
- **musl packaging keeps working.** The Linux packaging workflows extract
  exactly two checksums per target from the versioned V8 manifest and fail
  otherwise; upstream ships that file for 150.4.0 with Windows entries only, so
  the four linux-musl checksums are carried in the fork's copy.

## Retired

- **The Termux TLS root patch**, carried here for parity, is gone: upstream
  removed the client it wrapped and `reqwest` left the crate's dependencies, so
  it no longer compiled. MCP OAuth discovery now runs on the injected
  `codex-http-client`.
- **The fork's by-name session lookup test.** Upstream folded that lookup into
  `named_session_lookup`, which treats the SQLite row as authoritative and
  rejects unusable rollouts; the fork's fixture no longer described a valid
  session, and upstream's own tests cover the scenario more thoroughly.

## Verification

- `cargo check --workspace --all-targets`: clean.
- `cargo test -p codex-core --lib`: 2172 passed, 2 failed — both pre-existing and
  unrelated to this release: `post_sampling_token_estimate_is_disabled_by_always_on_sinks`,
  which fails inside the full suite and passes on its own, and
  `record_context_updates_emits_environment_item_for_time_changes`, an upstream
  test that only fails on a host whose timezone is `Europe/Berlin`.
- `cargo test -p codex-tui --lib`: 4031 passed, 24 failed — 23 long-standing
  snapshot mismatches plus the `relevant_memory_can_recall_aged_out_capsule`
  isolation defect. The snapshots record an upstream build stamped `0.0.0`, and
  this package reports its real version, so they cannot match by construction.
  None was accepted.
- Independently re-verified before release.
