# Codex VL 0.167.0-vl.1

Fork release on the upstream OpenAI Codex `rust-v0.167.0` base.

## Contents

- Upstream `rust-v0.167.0` merged with the fork feature set intact: Vivling,
  `/loop` and `manage_loops`, the VL UI, fork identity, the Termux and Android
  compatibility guards and the `-vl` managed daemon. Upstream highlights: the
  agent command center opens in embedded mode with `codex agents --no-daemon`
  and marks unread results and sessions, the terminal session picker switches
  between connected backends while keeping drafts, local image attachments
  preview in the composer and viewed image paths become clickable, Google
  Cloud Vertex AI setup joins onboarding behind the `gcp_setup_wizard`
  feature, system proxy support is exposed as an experimental setting, and
  patch details expand inline while an approval prompt is open. Upstream
  fixes: saved chats stay visible after model provider changes with an
  editable continuation prompt for chats that cannot resume, `Ctrl+L` clears
  the display while keeping history reachable through `Ctrl+T`, an exposed
  leading bang stays a literal draft, network approval prompts close when
  their requests end and serialize per endpoint, realtime V3 conversations
  preserve completed speech in chat history, and context compaction accounts
  for retained output from failed responses and responses without usable
  usage data. Upstream chores: DotSlash manifests reference the Cargo
  packages shipped with the release and Linux musl builds use fewer allocator
  arenas to reduce idle memory after conversations unload.
- Vivling session commands: `/vivling status`, `/vivling layout`, and
  `/vivling loop-strategy` parse case-insensitively with whole-word argument
  matching, `/vivling help` now lists `layout`, `loop-strategy`, and `memory`
  with deprecated long forms resolved by their full command spelling, the
  model errors say what the session commands actually do, `/loop` is
  reachable directly from the slash command, and status distinguishes
  managed-loop readiness from loop-owner readiness. The Vivling command
  reference (`docs/vivling_commands.md`) documents every subcommand.

## Install

```bash
npm install -g @mmmbuto/codex-vl@latest --allow-scripts=@mmmbuto/codex-vl
```

`@latest` points to this release once it is promoted; to pin it, use
`@mmmbuto/codex-vl@0.167.0-vl.1`. The platform builds are published as
`@mmmbuto/codex-vl@0.167.0-vl.1-<platform>` (`linux-x64`, `linux-arm64`,
`android-arm64`, `darwin-arm64`); the main package selects the right one.
The macOS arm64 package is built from source during installation.

## Verification

- Packaging builds run on the public GitHub workflows; the local smoke on the
